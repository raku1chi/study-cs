# 学び方 — 研究で効果が確かめられている学習法

> 同じ時間を使っても、学び方によって身につく量は大きく変わります。このページでは、認知心理学・教育心理学の研究で効果が繰り返し確かめられている学習法と、それをこのカリキュラムでどう使うかを説明します。

## 1. 「読んだ」と「できる」は違う

本を読み返したり、マーカーを引いたりすると、内容に見覚えが生まれ、「分かった」という感覚が得られます。しかしこの感覚は、思い出せる・使えることとは別物です。学習法の研究を広く検討した Dunlosky らのレビュー論文（2013 年）は、**繰り返し読むこと・ハイライトを引くことの効果は低く、自分をテストすること（想起練習）と、間隔を空けて学ぶこと（分散学習）の効果が高い** と評価しています。

このカリキュラムの構成は、この知見に沿っています。

| 研究で効果が高いとされる学習法 | カリキュラムでの仕組み |
|---|---|
| 想起練習（自分をテストする） | 各章の「理解度チェック」、演習 |
| 分散学習（間隔を空けて繰り返す） | 螺旋型の構成、週 1 回の復習（[学習ガイド](README.md#3-1-週間の学習リズム例)） |
| 交互練習（種類の違う問題を混ぜる） | 部をまたいだ復習、ケーススタディ |
| 精緻化・自己説明（なぜを説明する） | 「なぜ学ぶのか」「CTOの視点」、記述演習 |

## 2. 想起練習 — 思い出すことで記憶が強くなる

**記憶は、情報を入れるときではなく、取り出すときに強化されます**。Roediger と Karpicke の実験（2006 年）では、文章を繰り返し読んだグループより、一度読んだ後に思い出して書き出すテストをしたグループの方が、1 週間後の成績がはるかに良い結果になりました（テスト効果）。

このカリキュラムでの実践方法:

- **理解度チェックは、必ず解答を開く前に答える**。頭の中で「分かる気がする」で済ませず、紙やエディタに書き出す。書けなかったところが、あなたの本当の弱点です。
- **白紙に書き出す**: 章を読み終えたら本を閉じ、覚えていることをすべて書き出してから、本文と見比べる。
- **演習のテストを先に読みすぎない**: テストは仕様の確認に使い、実装は docstring から考える。

## 3. 分散学習 — 間隔を空けて繰り返す

同じ時間を使うなら、一度にまとめて学ぶより、**間隔を空けて何度かに分けて学ぶ** 方が長く記憶に残ります（分散効果）。忘れかけたころに思い出す努力をすることが、記憶を強くします。

実践方法:

- 章を終えたら、**1 日後・1 週間後・1 か月後** に理解度チェックを解き直す。
- 事実として覚えておくべきこと（2 のべき乗、レイテンシの桁、HTTP ステータスコード、分離レベルと異常の対応など）は、Anki などの間隔反復ソフトでカードにする。カードは自分の言葉で、1 枚 1 事実で作る。

## 4. 交互練習 — 種類の違う問題を混ぜる

同じ種類の問題を続けて解くと、「さっきと同じやり方」で解けてしまい、**どの手法を使うべきかを見極める力** が鍛えられません。種類の違う問題を混ぜる（インターリービング）と、その場では難しく感じますが、応用力が伸びることが知られています。

実践方法:

- 月 1 回の復習では、異なる部の理解度チェックを混ぜて解く。
- 「この問題はどの章の、どの考え方で解けるか」を先に言語化してから解く。
- CTO の実務は、まさに交互練習の連続です。障害 1 件の中に、ネットワーク・データベース・組織・顧客対応の問題が混ざっています。[15.4 ケーススタディ](../15-capstone/04-case-studies/README.md) はそのための練習です。

## 5. 精緻化と自己説明 — 「なぜ」を自分の言葉で説明する

新しい知識を、すでに知っていることと結びつけ、「なぜそうなるのか」を自分の言葉で説明すると、理解が深まります。物理学者リチャード・ファインマンの名を冠して語られる「ファインマン・テクニック」は、この考え方を実践しやすくしたものです。

1. 学んだ概念を、その分野を知らない人に説明するつもりで書く。
2. 説明に詰まった箇所や、専門用語でごまかした箇所を見つける。
3. そこだけ本文に戻って学び直し、もう一度説明する。
4. 例え話や具体例で、もっと簡単に説明できないか考える。

**学んだことをブログや社内勉強会で発信する** のは、この方法の最も効果的な形です。人に見せる文章を書くと、あいまいな理解はすぐに露呈します。CTO にとって「技術を平易に説明する力」は必須の能力なので（[14.4](../14-cto/04-executive-communication/README.md)）、一石二鳥です。

## 6. 望ましい困難 — 苦労することに意味がある

学習中に適度な困難があると、その場のパフォーマンスは下がっても、長期的な定着と応用力は高まります。心理学者 Robert Bjork はこれを「望ましい困難（desirable difficulties）」と呼びました。すぐに答えを見てしまうと、この効果を失います。

演習での実践方法:

1. **まず 20〜30 分、自力で考える**。紙に図を描き、小さな例を手で計算する。
2. それでも進めなければ、docstring のヒントや本文の該当箇所を読み直す。
3. 次に、解答例の **該当する関数だけ** を見る。すべてを読まない。
4. 解答例を閉じて、自分で書き直す。
5. テストが通ったら、解答例全体と自分のコードを比べ、違いとその理由を 3 行でメモする。

## 7. 意図的な練習 — 弱点に集中し、すぐにフィードバックを得る

心理学者 Anders Ericsson が研究した「意図的な練習（deliberate practice）」の要点は、**自分の能力の少し上の課題に、明確な目標と即時のフィードバックを伴って取り組む** ことです。ただ時間をかけるだけでは上達しません。

- 演習のテストは即時のフィードバックです。`python3 tools/check.py <章>` を小まめに実行しましょう。
- ★★★ の演習は「少し上の課題」です。すべて解く必要はありませんが、得意にしたい分野では必ず挑戦してください。
- [自己診断](self-assessment.md) で見つけた弱点の章を優先して学び直しましょう。

## 8. 作って学ぶ

コンピュータサイエンスには「自分で作ってみないと本当には分からない」ことが多くあります。このカリキュラムの演習で、UTF-8 デコーダ、キャッシュシミュレータ、インタプリタ、B+ 木、MVCC、Raft のリーダー選出、レートリミッタ、自動微分エンジンなどを作るのはそのためです。

演習を終えたら、次のような発展にも挑戦してみてください。

- 演習を **別の言語** で実装し直す（C、Go、Rust など）。
- 演習の実装に **機能を追加** する（例: インタプリタに配列を追加する、KV ストアにレプリケーションを追加する）。
- 本物の実装を **読む**（例: CPython の辞書の実装、SQLite のドキュメント、Raft の論文）。

## 9. 技術書と論文の読み方

**技術書** は、1 回で全部を理解しようとしないことが大切です。

1. **概観**: 目次・各章の冒頭と結論・図を見て、全体の構造をつかむ（30 分）。
2. **精読**: 自分に必要な章を、手を動かしながら読む。コードは写経して実行する。
3. **要約**: 1 章ごとに、自分の言葉で 1 ページの要約を書く。
4. **適用**: 仕事や演習で使ってみる。使ったことは忘れにくい。

**論文** の読み方としては、S. Keshav の "How to Read a Paper"（2007 年）で紹介されている 3 段階の読み方が有名です。1 回目は題名・要旨・見出し・結論だけを読んで全体像をつかみ、2 回目は図表を中心に内容を理解し、3 回目は自分で再現するつもりで細部まで読みます。第 7 部の分散システムや第 12 部の AI では、論文を読む力が特に役立ちます。

## 10. 学習ノートをつける

学んだことを記録すると、復習がしやすくなり、成長も実感できます。fork したリポジトリに `notes/` ディレクトリを作り、次のような形式で書くのがお勧めです（`notes/private/` は `.gitignore` で除外されているので、公開したくないメモはそこへ）。

```markdown
## 2026-10-05 / 6.3 トランザクション

- 学んだこと（自分の言葉で）: スナップショット分離では、2 つのトランザクションが
  別々の行を読んで別々の行に書くと、両方コミットできてしまう（書き込みスキュー）。
- 驚いたこと: PostgreSQL の REPEATABLE READ はスナップショット分離で、標準の定義と違う。
- 疑問: MySQL ではどうなる？ → 次回調べる
- 仕事への応用: 在庫の引き当て処理は、この問題を起こしていないか確認する。
```

## 11. 続けるための工夫

- **時間と場所を固定する**: 「平日の朝 7 時から 45 分、自宅の机で」のように決めると、意志の力に頼らずに続けられます。
- **小さく始める**: 疲れている日は「1 節だけ読む」「1 つのテストだけ通す」でかまいません。ゼロの日を作らないことが大切です。
- **進捗を見える化する**: `python3 tools/check.py` の合格数と [PROGRESS.md](../PROGRESS.md) のチェックが増えていくのは、それ自体が励みになります。
- **遅れても最初からやり直さない**: 数週間空いたら、直前の章の理解度チェックだけを解き直して再開しましょう。
- **持続可能なペースを守る**: 長期戦です。睡眠を削る学習は、記憶の定着を妨げるうえに続きません。

## 12. 詰まったときの対処法

| 状況 | 対処 |
|---|---|
| 本文の説明が分からない | 前提となる章に戻る。小さな例を手で計算する。コード例を少し変えて動かし、挙動を観察する |
| 演習の実装方針が立たない | docstring の例を手で追う。テストを 1 つだけ選び、それを通すことだけを考える |
| テストが失敗する理由が分からない | `python3 tools/check.py -v <章>` で詳細を見る。失敗したテストの入力を使って、関数を単体で呼び出して確かめる |
| 何時間も進まない | 30 分考えて進まなければ、ヒント → 解答例の該当部分の順に見る。進まない時間が長すぎると、学習効率は下がる |
| 質問したい | 「何をしようとして、何を試し、何が起きて、何を期待していたか」を書く。書いているうちに解決することも多い（ラバーダック・デバッグ） |

## さらに学ぶために

- Peter C. Brown, Henry L. Roediger III, Mark A. McDaniel "Make It Stick"（邦訳『使える脳の鍛え方 成功する学習の科学』NHK出版）— 想起練習・分散学習・交互練習などの研究を、一般向けに分かりやすくまとめた本。
- Felienne Hermans "The Programmer's Brain"（邦訳『プログラマー脳』秀和システム）— コードを読む・書く・学ぶときの認知の仕組みを、プログラマー向けに解説。
- Anders Ericsson, Robert Pool "Peak"（邦訳『超一流になるのは才能か努力か？』文藝春秋）— 意図的な練習の研究者自身による解説。
- John Dunlosky ほか "Improving Students' Learning With Effective Learning Techniques"（Psychological Science in the Public Interest, 2013）— 10 種類の学習法の効果を検討したレビュー論文。
- S. Keshav "How to Read a Paper"（ACM SIGCOMM Computer Communication Review, 2007）— 論文を効率よく読むための 3 段階の方法。
