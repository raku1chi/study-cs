# 第1部 コンピュータの基礎

> あなたが書いたプログラムは、最後には 0 と 1 のビット列として、トランジスタの ON/OFF で処理されます。この部では、ビットによる情報の表現から、論理回路と CPU、メモリ階層、そしてプログラムがビルドされて実行されるまでを、一本の流れとして積み上げます。「なぜ 0.1 + 0.2 が 0.3 にならないのか」「なぜ同じ計算量のコードが 10 倍遅いのか」「なぜ本番環境でだけ起動しないのか」に、原理から答えられるようになることが目標です。

## この部で身につくこと

- **表現を見抜く**: 整数・小数・文字がビット列としてどう表されるかを理解し、オーバーフロー・丸め誤差・文字化けを設計の段階で防げる。
- **CPU を組み立てる**: NAND ゲートから加算器・ALU・レジスタ・CPU までを積み上げ、機械語がフェッチ・デコード・実行される仕組みを説明できる。自分で CPU のエミュレータとアセンブラを書ける。
- **コンパイラの出力を読む**: x86-64 のアセンブリを読み、ARM64・RISC-V との違い（CISC と RISC）や、コンパイラの最適化が何をしたかを確かめられる。
- **性能を原理で説明する**: 性能方程式、パイプラインと分岐予測、メモリ階層のレイテンシの桁、局所性とキャッシュの仕組みを使って、コードやシステムの性能を見積もり、測定結果を解釈できる。
- **プログラムが動くまでを追える**: ビルド（プリプロセス・コンパイル・アセンブル・リンク）、ローダ、プロセスのメモリ配置、関数呼び出しとスタック、インタプリタと JIT を、実際のツールの出力で説明できる。
- **リスクを判断する**: 静的リンクと動的リンク、glibc と musl、x86 と Arm、CPU の脆弱性、メモリ安全性といった、配布・運用・セキュリティに関わる判断の根拠を持てる。

## 学習の進め方

### 章の順序と依存関係

```mermaid
flowchart LR
  C1["1.1 情報の表現<br>ビット・整数・小数・文字"] --> C2["1.2 論理回路とCPU<br>ゲートから命令の実行まで"]
  C1 --> C3["1.3 メモリ階層とキャッシュ<br>データはどこから来るか"]
  C2 --> C3
  C2 --> C4["1.4 プログラムが動く仕組み<br>ビルドから実行まで"]
  C3 --> C4
  C4 --> P3["第3部 プログラミング言語"]
  C4 --> P4["第4部 オペレーティングシステム"]
  C3 --> P4
```

- **1.1 → 1.2 → 1.3 → 1.4 の順に進むのが基本です**。1.2 は 1.1 の 2 の補数とオーバーフローを、ALU のフラグとして回路で実現します。1.3 のアドレスの分解は 1.1 のビット演算、1.4 のスタックフレームや呼び出し規約は 1.2 のアセンブリの読み方を前提にしています。
- **各章は「実物を見る」ことを重視しています**。本文には gcc・objdump・readelf などの実際の出力や、C のベンチマークの実測値が載っています。読むだけでも理解できるように書いてありますが、ぜひ自分の環境で同じコマンドを実行してみてください。結果が本文と違ったら、なぜ違うのかを考えることがいちばんの学びになります（性能の数値は環境によって大きく変わります）。
- **C の実行環境について**: 本文の C のコード例を動かすには、gcc または clang が必要です（[環境構築](../00-guide/setup.md)）。1.4 の `readelf`・`/proc/self/maps`・glibc の話題は Linux 固有なので、macOS では出力の形式が異なります（実行ファイルの形式が Mach-O で、`readelf` や `/proc` がありません）。WSL2 や Linux のコンテナ・仮想マシンを使うと、本文と同じ結果を確かめられます。Python の演習は、どの OS でもそのまま動きます。

### つまずきやすい点

- **符号付きと符号なし**: 1.1 の 2 の補数と、1.2 の C フラグ・V フラグの違いは、多くの人がつまずくところです。「同じビット列を 2 通りに解釈している」ことを、演習 2（ALU）の 4 ビットの全パターンのテストで確かめると腑に落ちます。
- **アセンブリの記法**: GCC の既定の AT&T 記法と、Intel 記法ではオペランドの順番が逆です。この部では主に Intel 記法（`-masm=intel`）を使っています。
- **ビット単位の計算**: キャッシュのアドレスの分解（1.3）や、再配置の相対アドレスの計算（1.4）は、紙に 2 進数を書いて手で一度計算してみるのが近道です。
- **演習の仕様を読む**: TinyCPU（1.2）や VM（1.4）の演習は、docstring の命令セットの表が「仕様書」です。実装を始める前に表を読み込み、分からない振る舞いはテストを読んで確かめてください。これは、実務で仕様書とテストから意図を読み取る練習にもなります。
- **経験者の進め方**: 理解度チェックに答えられる章は、★★★ の演習（TinyCPU、キャッシュのアクセスパターン、リンカ）だけ解いて先へ進んで構いません。CTO 準備トラックでは 1.1 と 1.3 が必修です。1.2 と 1.4 は、少なくとも「なぜ学ぶのか」と「CTOの視点」を読んでおきましょう（[学習ガイド](../00-guide/README.md)）。

## 到達度チェック

この部を修了したと言えるのは、次のことができるときです。

- [ ] 整数を 2 進数・16 進数・2 の補数で表し、固定幅の演算でオーバーフローが起きる条件を、ALU の C フラグと V フラグの違いとともに説明できる
- [ ] 浮動小数点数と文字コードの落とし穴を踏まえて、ID・金額・日時・文字列のデータ型を設計できる
- [ ] NAND ゲートから加算器・レジスタ・ALU を経て CPU に至る組み立てを説明し、簡単な CPU のエミュレータとアセンブラを書ける
- [ ] コンパイラが出力した x86-64 のアセンブリを読み、引数・ループ・条件分岐がどう実現されているかを説明できる
- [ ] 性能方程式とメモリ階層のレイテンシの桁を使って、CPU の比較やシステムの設計の性能を概算できる
- [ ] キャッシュの仕組みを説明し、アクセスパターン（行と列、AoS と SoA、ブロック化）やフォールスシェアリングが性能に与える影響を予測し、測定で確かめられる
- [ ] ソースコードが実行ファイルになり、プロセスとしてメモリに載り、関数を呼び出して動くまでの流れを、ツールの出力を示しながら説明できる
- [ ] 静的リンクと動的リンク、glibc と musl、x86-64 と ARM64 の違いが、配布・セキュリティ更新・移植性にどう影響するかを判断できる
- [ ] スタックバッファオーバーフローの仕組みと緩和策の限界を説明し、メモリ安全な言語を採用する意義を説明できる
- [ ] 第1部の演習のテストがすべて通る（`python3 tools/check.py 1`）

## この部の推薦図書・教材

- Randal E. Bryant, David R. O'Hallaron『コンピュータ・システム プログラマの視点から』（丸善出版）— この部全体の主教科書。第 2 章が 1.1、第 3〜5 章が 1.2、第 6 章が 1.3、第 7 章と第 9 章が 1.4 に対応する。カーネギーメロン大学の講義 "Introduction to Computer Systems"（15-213）の教科書で、講義資料も公開されている。
- Charles Petzold『CODE コードから見たコンピュータのからくり』（日経BP）— 電球とスイッチから論理回路・CPU までを物語のように積み上げる。この部の入門として、また全体像をつかみ直すために。
- Noam Nisan, Shimon Schocken『コンピュータシステムの理論と実装』（オライリー・ジャパン）— NAND ゲートから CPU・アセンブラ・VM・コンパイラまでを自分で作る。1.2 と 1.4 の演習の延長として最適で、「Nand2Tetris」として無料の講義と教材も公開されている。
- David A. Patterson, John L. Hennessy『コンピュータの構成と設計』（日経BP）— 論理回路・パイプライン・メモリ階層を体系的に学ぶ定番の教科書。
- Ulrich Drepper "What Every Programmer Should Know About Memory"（2007）— メモリとキャッシュについて、プログラマに必要な知識を詳しく解説した文書。
- John R. Levine『Linkers & Loaders』（オーム社）— リンカとローダを正面から扱った本。1.4 をさらに深めたい人に。
